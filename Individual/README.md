# Индивидуальная работа: Web-приложение Job Board

## 1. Описание проекта

Данный проект представляет собой традиционное web-приложение средней сложности, разработанное на языке PHP с использованием PostgreSQL в качестве базы данных. Приложение предназначено для публикации, просмотра и поиска вакансий.

Проект реализует серверную обработку данных, работу с базой данных, регистрацию и авторизацию пользователей, защищённые разделы сайта, роли пользователей, а также административную панель для управления данными.

Основная идея приложения — создать небольшой сайт вакансий, где обычные пользователи могут просматривать вакансии и добавлять новые записи, а администратор может управлять пользователями и вакансиями.

## 6. Описание архитектуры

Проект построен по модульному принципу, близкому к MVC-архитектуре.

Контроллеры принимают HTTP-запросы, вызывают нужные модели и подключают представления.

## 7. Структура базы данных

В проекте используются две основные таблицы:

- `users`
- `jobs`

### Таблица `users`

Таблица хранит данные пользователей.

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Поля таблицы:

| Поле | Описание |
|---|---|
| id | Уникальный идентификатор пользователя |
| name | Имя пользователя |
| email | Email пользователя |
| password | Хэш пароля |
| role | Роль пользователя: user или admin |
| created_at | Дата создания пользователя |

### Таблица `jobs`

Таблица хранит вакансии.

```sql
CREATE TABLE jobs (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(150) NOT NULL,
    company VARCHAR(150) NOT NULL,
    city VARCHAR(100) NOT NULL,
    salary NUMERIC(10, 2),
    employment_type VARCHAR(50) NOT NULL,
    description TEXT NOT NULL,
    is_remote BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Поля таблицы:

| Поле | Описание |
|---|---|
| id | Уникальный идентификатор вакансии |
| user_id | ID пользователя, который создал вакансию |
| title | Название вакансии |
| company | Название компании |
| city | Город |
| salary | Зарплата |
| employment_type | Тип занятости |
| description | Описание вакансии |
| is_remote | Формат работы: remote или office |
| created_at | Дата создания вакансии |

### Сценарий 1. Просмотр вакансий гостем

1. Пользователь открывает страницу `/jobs`.
2. Система получает список вакансий из базы данных.
3. Вакансии отображаются на странице.
4. Пользователь может использовать форму поиска.

### Сценарий 2. Регистрация пользователя

1. Пользователь открывает страницу регистрации.
2. Вводит имя, email и пароль.
3. Система проверяет данные.
4. Пароль хэшируется с помощью `password_hash()`.

### Сценарий 3. Вход пользователя

1. Пользователь открывает страницу входа.
2. Вводит email и пароль.
3. Система ищет пользователя по email.
4. Пароль проверяется с помощью `password_verify()`.
5. Если данные верны, создаётся сессия.

### Сценарий 4. Создание вакансии

1. Авторизованный пользователь открывает форму создания вакансии.

3. Система валидирует данные.
4. Вакансия сохраняется в базе данных.
5. Пользователь перенаправляется на список вакансий.

### Сценарий 5. Работа администратора

1. Администратор входит в систему.
2. Открывает административный раздел.
3. Просматривает пользователей и вакансии.

## 12. Безопасность

В проекте реализованы следующие меры безопасности:

- пароли хранятся только в виде хэшей;
- для хэширования используется `password_hash()`;
- для проверки пароля используется `password_verify()`;
- доступ к защищённым страницам проверяется через сессию;
- доступ к административным страницам разрешён только пользователям с ролью `admin`;
- запросы к базе данных выполняются через PDO prepared statements;
- вывод пользовательских данных экранируется через `htmlspecialchars()`;
- данные форм проходят проверку на стороне клиента и сервера.

## 13. Ответы на контрольные вопросы

### 1. Зачем нужна аутентификация пользователей?

Аутентификация нужна для проверки личности пользователя. С её помощью система понимает, кто именно вошёл в приложение, и может предоставить доступ к личным или защищённым разделам сайта.

### 2. Чем аутентификация отличается от авторизации?

Аутентификация отвечает на вопрос: «Кто этот пользователь?». Авторизация отвечает на вопрос: «Что этому пользователю разрешено делать?». Например, пользователь может войти в систему, но доступ к административной панели будет только у пользователя с ролью `admin`.

### 3. Почему пароли нельзя хранить в открытом виде?

Пароли нельзя хранить в открытом виде, потому что при утечке базы данных злоумышленник сразу получит доступ к аккаунтам пользователей. Поэтому пароли нужно хранить в виде хэшей.

### 4. Как работает `password_hash()`?

Функция `password_hash()` создаёт безопасный хэш пароля. В PHP по умолчанию используется алгоритм bcrypt. Хэш является однонаправленным, поэтому получить исходный пароль из хэша невозможно.

### 5. Как работает `password_verify()`?

Функция `password_verify()` сравнивает введённый пользователем пароль с хэшем, который хранится в базе данных. Если пароль соответствует хэшу, функция возвращает `true`.

### 6. Что такое SQL-инъекция?

SQL-инъекция — это атака, при которой злоумышленник пытается вставить вредоносный SQL-код в пользовательский ввод. Такая атака может привести к чтению, изменению или удалению данных из базы.

### 7. Как PDO prepared statements защищают от SQL-инъекций?

Prepared statements отделяют SQL-запрос от пользовательских данных. Данные передаются как параметры, поэтому они не выполняются как SQL-код.

Пример:

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE email = :email');
$stmt->execute(['email' => $email]);
```

### 8. Зачем использовать сессии?

Сессии используются для хранения информации о состоянии пользователя между запросами. Например, после входа пользователя его ID и роль сохраняются в сессии, чтобы система понимала, что пользователь авторизован.

### 9. Что такое роль пользователя?

Роль пользователя определяет его права в системе. В проекте используются роли `user` и `admin`. Обычный пользователь может создавать вакансии, а администратор может управлять пользователями и всеми вакансиями.

### 10. Почему нужно экранировать вывод через `htmlspecialchars()`?

Функция `htmlspecialchars()` защищает от XSS-атак. Она преобразует специальные HTML-символы в безопасный вид, поэтому вредоносный код не выполняется в браузере.
